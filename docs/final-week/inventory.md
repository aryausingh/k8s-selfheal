Two schema facts to get right before the report is assembled, because they
look like contradictions and are not:

1. The owner-2 draft describes the shared audit schema as **eight** fields.
   `safety.AuditEntry` as merged declares **nine**: `pod` was restored,
   because without it a line cannot be attributed to a workload when three
   Deployments are remediated concurrently — which is how the final runs were
   executed. The code is right; the sentence in the draft needs updating.
2. Lines in `sage-final-runs/` carry **seven** keys, not nine: `workload` and
   `armLabel` are absent. The image deployed on the VM for those runs predates
   the `--audit-workload` / `--audit-arm` flags that populate
   `safety.AuditMetadata`; the kind cross-check runs under `runs/`, produced
   after the flags landed, do carry `armLabel`. No reported number is affected
   — `results.py` reads workload and arm from each run's `meta.json`, not from
   the audit line — but do not claim in the report that every archived line
   carries the full schema, because an examiner can open the file.
